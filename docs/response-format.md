# 공통 API 응답 형식

모든 `/api/v1` 응답은 아래 포맷을 따른다. (기준: API 명세서 초안)

## 성공 응답

```json
{
  "success": true,
  "data": {},
  "message": null
}
```

## 실패 응답

```json
{
  "success": false,
  "error": {
    "code": "UNSUPPORTED_FILE_TYPE",
    "message": "지원하지 않는 파일 형식입니다.",
    "detail": {}
  }
}
```

- `code`는 스크린 상수 문자열(예: `UNSUPPORTED_FILE_TYPE`)로, 클라이언트가 분기 처리할 수 있게 한다.
- `message`는 사용자에게 보여줄 수 있는 한글 메시지.
- `detail`은 추가 디버깅/검증 정보(옵션).

## 공통 HTTP Status Code

| Status | 의미 | 사용 예시 |
| --- | --- | --- |
| 200 | 성공 | 조회, 처리 완료 |
| 201 | 생성 성공 | 리소스 생성 |
| 202 | 처리 접수 | 분석, 수집처럼 시간이 걸리는 비동기 작업 |
| 204 | 응답 본문 없음 | 로그아웃 등 |
| 400 | 잘못된 요청 | 필수 파라미터 누락 |
| 401 | 인증 실패 | 토큰 없음/만료 |
| 403 | 권한 없음 | 접근 권한 부족 |
| 404 | 리소스 없음 | 존재하지 않는 ID |
| 409 | 충돌 | 중복 실행 |
| 413 | 파일 용량 초과 | 업로드 제한 초과 |
| 415 | 지원하지 않는 미디어 타입 | 허용되지 않은 파일 형식 |
| 422 | 검증 실패 | 스키마 검증 오류 |
| 429 | 호출 제한 | 외부 API 호출한도 초과 |
| 500 | 서버 오류 | 예기치 않은 서버 오류 |
| 503 | 외부 서비스 오류 | 외부 API/OCR/LLM 장애 |

> 참고: 이 문서는 응답의 "형태"만 고정한다. 실제 엔드포인트 목록과 필드 정의는 API 명세서에서 관리한다.
