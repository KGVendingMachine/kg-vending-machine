# 사업계획서 정규화 — PSST 공통 요소 매핑

서로 다른 서식의 사업계획서(뉴엑스피어형·아슬론 상세본형 등)를 하나의 표준 스키마로 정규화하기 위한 기준표다. PSST(Problem·Solution·Scale-up·Team) 대분류를 축으로, 서식별로 다르게 표현되는 항목을 공통 핵심 요소로 매핑한다.

| PSST 대분류 | 뉴엑스피어 | 아슬론 상세본 | 공통 핵심 요소 |
| --- | --- | --- | --- |
| 일반현황 | 기업명 / 아이템명 / 업종 / 대표자 | 회사개요 (설립일 / 사업자구분 / 타겟시장) | 기업명, 대표자, 설립일, 아이템명, 업종, 사업자구분(개인/법인) |
| P (문제인식) | 아이템 소개 내 문제점 인식 | 개발동기 (질환 통계·기존 진단법 한계) | 시장/고객 문제 정의, 통계적 근거, 기존 대안의 한계 |
| S (실현가능성) | 핵심기능, 독창성 4가지 | 제품 요약, 지적재산권(특허 3건) | 제품·서비스 설명, 핵심기술, 차별성, 지적재산권 현황 |
| Sc (성장전략) | 시장규모, 타깃고객, 비즈니스모델 | TAM/SAM/SOM, BMC 9블록, SWOT, 투자유치계획, 매출계획 | 시장규모(TAM/SAM/SOM), 타깃고객, 수익모델, 매출·자금계획 |
| T (팀구성) | 대표자 학력/경력 요약 | 대표자 상세이력, 팀원별 역량표, 채용계획 | 대표자 역량, 팀원 구성, 추가 채용계획 |
| 공통 부속서류 | 사업자등록증(사업자 증빙) | (경진대회 서류엔 참가자격/개인정보동의) | 사업자등록증, 법인등기부등본, 신청자격 증빙 |

## 적용 원칙

- 서식마다 항목명·구조가 달라도, 위 표의 "공통 핵심 요소" 열이 정규화 스키마의 필드 기준이 된다.
- 원본 서식에 없는 항목(예: 아슬론 상세본에 없는 참가자격 서류)은 공란으로 두고 자동 추론하지 않는다.
- 새 서식이 추가되면 이 표에 열을 하나 추가해 매핑을 검증한 뒤, 공통 핵심 요소 열이 바뀌지 않는지 먼저 확인한다.

## 정규화 스키마 필드 (실제 반영 대상)

위 매핑표에서 세 문서(뉴엑스피어·아슬론 상세본·경진대회 서류)에 실제로 반복 등장한 필드만 추려 정규화 스키마 필드명으로 확정한다.

| 그룹 | 필드 | 근거 (어느 문서에 있었나) |
| --- | --- | --- |
| 일반현황 | `company_name`, `representative`, `founded_date`, `business_type`(법인/개인), `item_name`, `industry` | 3개 문서 공통 |
| 문제인식 (P) | `problem_statement`, `market_pain_point`, `supporting_stats` | 뉴엑스피어(교육시장 문제), 아슬론(질환 통계) |
| 실현가능성 (S) | `product_summary`, `core_tech`, `differentiators[]`, `ip_status`(특허·상표 수) | 뉴엑스피어(4대 독창성), 아슬론(특허 3건 명시) |
| 성장전략 (Sc) | `target_market`, `tam_sam_som`, `revenue_model`, `funding_plan`, `sales_forecast` | 아슬론이 가장 상세 (TAM $71.8B, SAM $27.8B 등 수치 명시) |
| 팀구성 (T) | `founder_background`, `team_members`, `hiring_plan` | 3개 문서 모두 팀 파트 보유, 아슬론이 표 형태로 가장 구조화 |
| 사업자 증빙 | `business_registration_number`, `registration_date`, `biz_category` | 아슬론 사업자등록증 이미지에서 확인 (예: 382-81-03437, 개업 2023.08.30) |

## 문서별 완성도 진단

정규화된 필드를 기준으로, 사업계획서 하나가 들어왔을 때 PSST 그룹별로 "충족/미흡"을 판정하고 근거를 남긴다. 세 문서를 비교하면 그룹별 완성도 편차가 크므로, 아래 기준으로 진단한다.

| 그룹 | 충족 판정 기준 | 미흡 시 표시 문구(예) |
| --- | --- | --- |
| 일반현황 | 6개 필드 모두 채워짐 | "대표자/설립일 등 기본 정보가 비어 있어요" |
| 문제인식 (P) | `problem_statement` + `supporting_stats`(통계·수치 근거) 존재 | "문제 제기는 있으나 통계적 근거가 부족해요 — 예: 아슬론처럼 질환 통계 수치를 넣으면 신뢰도가 올라가요" |
| 실현가능성 (S) | `differentiators[]` 2개 이상 + `ip_status` 명시 | "차별성은 있으나 지적재산권(특허/상표) 현황이 없어요" |
| 성장전략 (Sc) | `tam_sam_som` 수치 + `revenue_model` + `funding_plan` 모두 존재 | "시장규모는 언급됐지만 TAM/SAM/SOM을 숫자로 쪼개지 않았어요 — 아슬론처럼 TAM $71.8B, SAM $27.8B식 수치가 있으면 사업 정합 점수가 올라가요" |
| 팀구성 (T) | `team_members`가 표/리스트 형태로 역할·역량까지 명시 | "대표자 이력만 있고 팀원 구성·채용계획이 없어요" |
| 사업자 증빙 | `business_registration_number` + `registration_date` 존재 | "사업자등록번호·개업일이 확인되지 않아 업력 요건 자동 대조가 불가능해요" |

세 문서 중에서는 아슬론 상세본이 성장전략(TAM/SAM/SOM 수치, BMC, SWOT)과 팀구성(표 형태)에서 가장 완성도가 높고, 뉴엑스피어는 일반현황·실현가능성은 갖췄으나 성장전략의 수치 근거가 상대적으로 얕다. 경진대회 서류는 PSST 본문보다 참가자격·개인정보동의 등 부속서류 위주라 PSST 6개 그룹 커버리지 자체가 낮다.

### 자격요건 대조와의 연결

`business_registration_number` / `registration_date` / `biz_category`는 [`matching-pipeline.md`](./matching-pipeline.md)의 AI 매칭 스코어링 단계와 [`MatchDetailPage`](../frontend/src/pages/MatchDetailPage/MatchDetailPage.tsx)의 "자격요건 대조"(중소기업 여부·업력 3년 이상 등)를 자동으로 계산하는 데 쓰인다. 이 세 필드가 비어 있으면 자격요건 대조 자체가 불가능하므로, 완성도 진단에서 "미흡" 판정 시 우선순위를 가장 높게 둔다.
